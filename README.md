# 660710763-tasks

โค้ดตัวอย่างสำหรับฝึกตรวจโค้ดที่ AI เขียน เทียบกับ requirement (Verifying AI-Generated Code Against Requirements)
รายวิชา 520461-165 Software Requirement Specification and Management ภาควิชาคอมพิวเตอร์ คณะวิทยาศาสตร์ มหาวิทยาลัยศิลปากร

## ในนี้มีอะไร

ตัวอย่างจองคิวตรวจสุขภาพ ที่ AI ทำ T-01 ถึง T-03 ไว้แล้ว (สร้างตาราง, GET /slots, POST /bookings)
test ทั้งหมดขึ้น passed และทีมตรวจ 5 ข้อแล้วว่าผ่าน
**แต่ยังมีจุดที่โค้ดไม่ตรง requirement ซ่อนอยู่** หน้าที่ของเราคือหาให้เจอด้วย 3 เครื่องมือ

1. แปลง AC เป็น test cases แล้วให้ AI เขียน test ตามนั้น (`/testcases`)
2. ทำตารางตามรอย spec โค้ด test (`/verify` ได้ `rtm.md`)
3. อ่านโค้ดด้วยสายตา Requirement Engineer 5 คำถาม


## Reflection
วันที่ 7 OCT การตรวจ Code ของ AI เราได้เรียนรู้ว่า
1. test ผ่านไม่ได้แปลว่าโค้ดถูก test เดิมเช็กแค่ status 201 จึงไม่เจอบั๊กจองได้ตอนเหลือ 0 ที่ ต้องมี test จาก AC ที่ assert ผลในข้อมูลจริงทุกส่วนของ Then
2. AI มักเพิ่มของที่ spec ไม่ได้สั่ง และตัดสินใจแทนทีมเงียบ ๆ เช่น ปุ่มยกเลิกคิวที่อยู่ใน Out of scope, เลข 14 วันแทน 30 วัน, เลขคิว A001 ที่ยังรอ Q-02 และเก็บเลขบัตรประชาชนลง log
3. ต้องตามรอยจาก spec ไปโค้ดและ test (RTM) แล้วเปิดโค้ดยืนยันด้วยตาเอง เพราะ AI อ้าง ID ในคอมเมนต์ผิดเรื่องได้ และคนต้องเป็นคนตัดสินว่าจะแก้อะไร
